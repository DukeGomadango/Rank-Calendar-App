# 機能要件（Functional Requirements）

## 機能一覧（概要）

1. **デイリーランクの見える化** — 目標+・実績+、ボーダー、スキップパスを日別に記録し、週の + 合計やランクアップ目安を表示。
2. **カレンダー & データ表** — スケジュール・イベントをカレンダー形式と表形式で表示・編集。月・週ナビで過去・未来を確認。
3. **リスナーへの共有** — 招待リンクとロールによる権限制御。簡易表示・詳細表示の切り替え。
4. **プライバシー重視** — OCR はクライアントのみで実行し、画像をサーバーに送信・保存しない。

## 主要機能の詳細

### 1. スケジュール（日別エントリ）

- **登録・編集できる項目**
  - 日付（JST 想定）
  - 目標+（target_plus）
  - 実績+（actual_plus）
  - ボーダー +2 / +4 / +6（border_plus2, border_plus4, border_plus6）
  - スキップパス使用有無（skip_pass_used）
  - 参加イベント（event_id）
  - メモ（memo）
  - 配信内容（stream_content）
  - 配信内容色（stream_content_color）
- **配信内容（stream_content）表示**: 配信内容は `view_schedule_stream` を持つリスナーに表示されます（色は `stream_content_color` を使用）。
- **集計ルール**
  - 週は JST 月曜始まりで区切る。
  - スキップパス使用日は週の + 集計から除外。
  - 実績+が未入力の日は 0 扱い。配信休みは actual_plus=0, skip_pass_used=false で表現。
- **ランク判定（ドメイン）**
  - 週の + 合計が **+18** で「翌日 0:00 にランクアップ可」とみなす。
  - **+12** で「維持」とみなす。

### 2. 時間付きスケジュール（カレンダー予定 / calendar_schedules）

- **登録・編集できる項目**（オーナー）
  - 開始日（date）
  - 終了日（end_date: null の場合は同日扱い）
  - 開始時刻 / 終了時刻（start_time, end_time: 全日なら null）
  - 全日（is_all_day）
  - タイトル（title）
  - 種別（kind: `stream` / `personal` / `secret`）
  - 表示区分（visibility: 仕様としては保存されるカラム）
  - 色（color_id）
  - メモ（memo）
- **表示制御（リスナー）**
  - `kind` に応じて、権限 `view_schedule_stream` / `view_schedule_personal` / `view_schedule_secret` が必要です。
  - オーナーは全ての予定を表示できます。

### 3. カレンダー・データ表

- **カレンダー**: 月表示・週表示でスケジュールとイベントを表示。日付クリックで登録・編集。
- **週表示（時間軸）**（編集権限がある場合）: 15 分グリッド・スナップ（ドラッグ移動・範囲選択の新規作成・リサイズ）。重なる予定は列分割表示。ドラッグ中はドロップ先に仮ブロックで時刻プレビュー。上下ハンドルで開始/終了のリサイズ（タッチ向けに広い当たり判定）。週グリッドにフォーカスがあるとき **Ctrl+Z / Ctrl+Shift+Z または Ctrl+Y** で Undo/Redo、**Ctrl+C / X / V** でコピー・切り取り・貼り付け（入力欄フォーカス時は無効）。
- **データ表**: 日付範囲を指定し、テーブル形式で一覧表示・編集。@tanstack/react-table を使用。
- 表示モード: **簡易表示（simple）** と **詳細表示（detailed）** を切り替え可能（ViewModeProvider / localStorage `iriam_view_mode`）。設定画面の「表示設定」で変更可能。
- **テーマ**: ライト/ダーク/システムの切り替え（ThemeProvider / localStorage `iriam-theme`）。ダッシュボード右上の ThemeToggle で変更可能。

### 4. イベント

- カレンダーに紐づくイベントを登録（名前、開始日、終了日）。
- スケジュールエントリから「参加イベント」として参照可能。

### 5. 共有・招待

- **ロール**: 閲覧可能な権限の組み合わせを定義（例: カレンダー表示、データ表表示、ボーダー表示、メモ表示、目標実績表示、ランク表示、イベント表示）。
- **招待リンク**: ロールを紐づけた招待リンクを発行。リンク経由でユーザーが参加すると、そのロールの権限でカレンダーを閲覧可能。
- **権限種別**（PermissionKey）
  - 基本情報: `view_calendar`, `view_table`, `view_borders`, `view_memo`, `view_target_actual`, `view_rank`, `view_events`
  - 予定（スケジュール）: `view_schedule_stream`, `view_schedule_personal`, `view_schedule_secret`
- 編集（スケジュール・イベントの変更）は **オーナーのみ**。共有先は閲覧のみ。

### 6. OCR（ボーダー読み取り）

- クライアント側で tesseract.js を使用。画像をサーバーに送信せず、ブラウザ内でのみ処理。
- 読み取り結果をボーダー等の入力として利用可能（ボーダー +2/+4/+6・アンスコ基準値はいずれも 0〜9,999万まで対応）。

## ユースケース（利用の流れ）

1. **アカウント作成** — メールまたは OAuth でサインアップ。
2. **スケジュール登録** — ダッシュボード・カレンダー・データタブで、日付ごとに目標+・実績+・ボーダー・スキップパス・イベント・メモ（配信内容含む）を入力。必要に応じて時間付きの予定（カレンダー予定）も登録。
3. **必要に応じて共有** — 共有タブでロールを作成し、招待リンクを発行。リスナーに権限を付与してスケジュールを安全に共有。
4. **閲覧** — 招待されたユーザーは、付与された権限の範囲でカレンダー・データ表・ランク情報などを閲覧（簡易/詳細表示の切り替え可）。

## 非機能要件（現状の整理）

- **認証**: Supabase Auth（メール or OAuth）。セッションはサーバー・クライアントで Supabase クライアント（`@supabase/ssr`）経由で利用。
- **データ永続化**: Supabase（PostgreSQL）。スキーマは `iriam`。
- **プライバシー**: OCR 画像はサーバーに送信・保存しない。トラッキングは行わない方針。
- **多言語・タイムゾーン**: 日付は JST（Asia/Tokyo）基準。UI は日本語を想定。
- **テーマ**: ライト/ダーク/システム対応。localStorage で永続化し、初回描画時のフラッシュを抑えるスクリプトをルートで実行。
- **利用料金**: 現時点では無料で提供。
